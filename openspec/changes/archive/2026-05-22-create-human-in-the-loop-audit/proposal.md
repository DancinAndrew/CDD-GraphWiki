# Proposal - Human-in-the-Loop & Audit Logging (人機協同與合規審計日誌)

本變更提案旨在為 CDD-GraphWiki 引入人工審查生命週期管理（Human-in-the-Loop）與防篡改合規審計追蹤（Audit Logging），實現高合規敏感度場景下的安全閉環，並能一鍵導出符合監管審查要求的合規審計報告。

## Why

在反洗錢（AML）與客戶盡職調查（CDD）等極度嚴謹的合規場景中：
1. **機器推理的局限性**：儘管規則與圖譜推理極度精準，但機器決策不能（也不應）完全取代合規專家的最終裁決。高風險政要（PEP）、未明股權或複雜政策衝突等情境，必須經過「人機協同」審批流程。
2. **審計可追溯性與監管要求**：金融監管機構（如 MAS、FATF）要求金融機構在進行 CDD 決策時，必須保留「不可篡改、完全可審計」的決策追蹤軌跡（Audit Trail）。系統必須能夠證明某個決策是基於哪一版法規、在什麼時間、經過了哪些圖譜節點推理以及是哪位合規官進行的最終簽批。

## What Changes

我們將在系統中新增以下功能與架構：
1. **`ReviewCase` 強型別合約**：擴充 Pydantic 資料模型，以標準化管理需要人工審查案件的生命週期（包含審查理由、狀態扭轉、審查筆記等）。
2. **防篡改審計日誌引擎 (`AuditLogger`)**：實作一個基於級聯雜湊（Hash Chain）的防篡改鏈式日誌引擎，將每一次系統推理、衝突識別與人工覆寫的操作均寫入鏈式審計日誌中。
3. **人機協同控制引擎 (`ReviewCaseManager`)**：管理審查案件。當合規官批准或拒絕某個案件時，自動更新關聯 `CDDChecklist` 的狀態，覆寫機器決策，並無縫嵌入審批人軌跡。
4. **一鍵導出合規審計報告 (`AuditReportGenerator`)**：生成格式美觀的 Markdown 與 HTML 格式合規審計包，合為一體呈現原始客戶情境、圖譜推理軌跡、條文 Citation 溯源與人工審批完整日誌。

## Capabilities

* **人機審批決策覆寫**：支持由合規官對機器決策進行人工介入，並更新 checklist 資料。
* **日誌鏈式雜湊校驗**：系統能自我檢測審計日誌是否遭受篡改（若日誌被刪除或改動，鏈式雜湊將會斷裂失效）。
* **合規審計包導出**：提供一鍵導出的可視化 HTML 審計報告，採用優雅的暗黑磨砂玻璃美學，支持監管機構隨時稽核。

## Impact

* **安全與防禦性**：保障所有人工決策的法理依據可溯源、可問責。
* **零依賴與強健度**：完全在 Python 標準庫與 Pydantic 框架下實現防篡改日誌與報告導出，不引入額外的重型資料庫或第三方套件。
